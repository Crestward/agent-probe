agent-probe

Attack LLM agents and their MCP tool servers — then measure the defence.
A red-teaming & guardrail benchmark for agentic AI · mapped to OWASP LLM Top 10 (2026) + MITRE ATLAS · Python 3.12 · live dashboard + CLI

Why I built it. Most “AI security” projects stop at a screenshot of a single prompt injection working. I wanted the opposite — a measurement instrument that treats agent defence as a number you can regression-test. agent-probe attacks a tool-using LLM agent across realistic channels (email, documents, CRM fields, support tickets, web pages, and the MCP tool layer itself), then measures how much a guardrail actually moves the Attack Success Rate — the Defence Delta. It aims to be the standardized, reproducible vulnerable-target benchmark for MCP/agent attacks that the red-teaming literature (arXiv 2611.04271) notes is still missing. Everything runs against a free local model by default (zero cloud spend); you can point it at your own model in one flag.

Headline result — 31 attacks, two targets

Every attack runs against a local qwen2.5:7b and Claude Haiku 4.5 (the small, fast model most teams actually put behind RAG and agent tools), baseline and with one guardrail. The point is the spread: a single ASR number hides everything interesting.

What the spread says (this is why it's a benchmark, not a demo): Haiku shrugs off everything qwen falls for — injection, jailbreak carriers, tool-poisoning, rug-pull, secret disclosure all drop to 0%. But Haiku is more vulnerable where it counts for agents: scope violations (a support bot coerced into writing code / running SQL / swapping persona — 50%) and excessive-agency actions (33%). qwen's weakness is injection/exfiltration; Haiku's is agency and staying in role. One ASR number would have hidden that completely.

What I learned

  • Different models fail at different things. “Which model is safest” is the wrong question; “safe against which failure class, for my agent's role and permissions” is the right one.
  • The fix was a better attack, not a weaker target. Naive injection scores 0% on every model. I engineered attacks from the literature instead — AgentDojo's important_instructions template lands on qwen2.5 at 100% on its own. Pulling a rigged/uncensored model would have made the benchmark worthless.
  • Constraining actions beats detecting every injection. The guardrail's least-privilege egress allow-list does the heavy lifting: once the model can't email the attacker, a successful injection has nowhere to go.
  • Honesty is the product. Guarded ASR never hits 0% — scope violation survives the exfil guardrail on both models. The dashboard shows the cells the defence didn't fix, and recommend flags them as needing a different control.

What it does

8 attack families across 10+ channels, each a readable YAML with a verified MITRE ATLAS id.
Measures the defence — ASR before/after one guardrail, overall and per family, with PR / ASR-behind-filter split.
Prescribes the fix — recommend outputs prioritized, OWASP/ATLAS-mapped mitigations per failing family.
Bring your own model — local (Ollama), Anthropic, OpenAI, DeepSeek, or any OpenAI-compatible endpoint.
Live dashboard — cross-model scoreboard, Defence-Delta bars, outcome heatmap, and a trace explorer.
Reproducible — 50 deterministic, keyless tests + committed result snapshots; every number traces to a file.
